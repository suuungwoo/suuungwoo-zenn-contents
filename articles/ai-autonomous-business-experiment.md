# 依頼は1メッセージだけ

2026年7月19日、Claude Code(Claude Fable 5)に次の趣旨の依頼を1通だけ送りました。

> 最新のAIエージェントでどこまで自律的にやれるかテストしたい。ビジネスを考えて、プロダクトが必要なら作って、マーケが必要ならそれも作って、少額でもよいので短時間で利益を出してほしい。ビジネスモデルもターゲットもプロダクトも全部任せる。Codexに渡せる作業は渡して、Fable 5は指揮に専念。私がやることは最小にしてほしい。

この記事は、その後にAI側が何をしたかの実験ログです。私(人間)は依頼後、この記事の公開ボタンを押すまでの間、意思決定をほぼしていません。

# 前提: 権限設計だけは先に決めてあった

丸投げが成立した最大の理由は、モデルの性能そのものより、事前に運用ルールをMarkdownで定義してあったことです。私はエージェントの長期コンテキストをローカルのMarkdownリポジトリ(正本ファイル群+運用ルール)として管理しており、委任範囲は「停止条件3つ」方式で決めています。

1. 触ってはいけない特定資産(退職済み組織のアカウント等)
2. 金銭上限の超過、新しい支払先・契約
3. 不可逆・対外操作(公開、送信、購入確定、大量削除)

これ以外は既定で自律実行。つまりAIは「公開ボタンの直前まで」は確認なしで進んでよい、という契約です。

# 指揮役(Claude Fable 5)がやったこと

依頼から実際に行われた手順は次の通りです。

1. **資産の棚卸し**: ローカルの長期コンテキストを読み、次に実ブラウザで販売チャネル候補のログイン状態を確認。Zennがログイン済み・GitHub連携済み・収益出金は販売後の申請でよい、と観測。
2. **事業の選定**: 「Zenn有料本(500円)+無料GitHubテンプレートrepo+無料集客記事」を採択。理由は、新規アカウント作成も新規支払先も不要(停止条件に非該当)、原価ほぼゼロ、そして売る knowledge の実体が既に手元にあること。既存プロダクトの公開前倒し案、note案、Gumroad案は、人間の作業が増える・チャネル未確認などの理由で却下。
3. **計画の正本化**: 採択理由・役割分担・サニタイズ条件・収益記録欄を持つ計画ファイルをリポジトリに作成。
4. **Codexへの委任**: 実装・執筆の全量をCodexへ委任。ネットワーク許可はgit clone分だけ、pushと公開は禁止、という条件付き。

# 実装役(Codex)がやったこと

Codexは1回の委任で以下を納品しました。

- **テンプレートrepo**: AIを秘書化する運用設計(AGENTS.md、事実ラベル6種、停止条件3つ、ワークフロー)の汎用テンプレート一式
- **有料本の原稿**: 10章・約20,000字。`published: false`、価格500円でローカルコミットまで
- **無料集客記事**: 設計の全体像を解説する約3,000字

個人情報の混入(サニタイズ)は、Codexの自己チェックに加えて指揮側が実在固有名詞をgrepして二重に検証しました。

# 面白かったのは品質監査

指揮役が納品物を検品したところ、**全10章の末尾が同一パターンの短い断片文3行で終わっている**ことを検出しました。「承認対象を具体化します。」のような、字数合わせの痕跡です。指摘をCodexに差し戻し、各章の締め段落として書き直させました。

AIがAIの成果物をレビューして差し戻す、という工程が実際に品質へ効いたのは収穫でした。逆に言うと、1エージェントの一発出力をそのまま売り物にするのはまだ危険です。

# 人間がやったこと・やること

- 依頼メッセージを1通送った
- 公開の一括承認(このリポジトリのルール上、公開・投稿は必ず人間が承認する)
- 売上が立ったら出金申請(銀行口座の登録はAIには渡していない)

以上です。逆に、AIがどれだけ自律的でも公開・金銭の最終ボタンだけは人間に残す、という設計は今回も崩していません。
