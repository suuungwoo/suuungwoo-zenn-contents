# AIエージェントを「秘書」として使うには

Claude CodeやCodexに質問すると、調査、文章作成、コード編集まで短時間で進められます。一方で、セッションが変わると前提が消えたり、以前の推測が事実のように扱われたりします。

この問題を、モデルの記憶力だけで解決しようとしない方法があります。AIが参照する長期コンテキストを、Markdownファイルの集合として手元に置く方法です。私はこれをPersonal AI Systemのportable context layerと呼んでいます。

portable context layerは、特定ツールの組み込み記憶に依存しないコンテキスト層です。エージェントを切り替えても、同じ正本、同じ運用ルール、同じ事実ラベルを参照できます。人間が直接読めるため、誤りを見つけたときに修正でき、Gitの差分で変更履歴も確認できます。

# 最小構成はファイルを増やしすぎない

最初に必要なのは、次のような小さな構成です。

```text
personal-ai-system/
├── AGENTS.md
├── CLAUDE.md
├── 00_START_HERE.md
├── context/
│   ├── 00_index.md
│   ├── source_of_truth.md
│   ├── profile.md
│   ├── preferences.md
│   ├── goals.md
│   └── constraints.md
├── tasks/
│   └── delegated_actions_policy.md
├── workflows/
│   ├── session_start.md
│   ├── memory_maintenance.md
│   └── daily_brief.md
└── inbox/
    └── unsorted.md
```

`AGENTS.md`には、AIへ恒久的に適用する応答スタイル、事実の扱い、完了主張の検証方法を書きます。`CLAUDE.md`はClaude Code向けの入口として、共通ルールを参照する薄いラッパにします。個人の目標や回答の好みは`context/`に置き、ルールとデータを分離します。

`source_of_truth.md`には、どの事実をどのファイルで管理するかを登録します。例えば、目標は`goals.md`、回答の好みは`preferences.md`、制約は`constraints.md`です。同じ情報を日次ブリーフや案件メモへ全文コピーしません。要約を置く場合も、正本への参照を残します。

まだ分類できないメモは`inbox/unsorted.md`へ置きます。inboxを長期保管庫にせず、週次または月次で正本へ移すか、不要なものを整理します。

# 事実を6つのラベルで管理する

記憶汚染を防ぐには、情報の内容だけでなく、確度を保存します。

- **確認済み**: 利用者が明示した、または一次情報で確認した
- **観測済み**: 画面、ツール、ローカルファイルから観測した
- **取込済み**: エクスポートや既存資料から取り込んだ
- **推定**: 複数の情報から推論した
- **要再確認**: 古い可能性がある
- **不明**: 現時点で判断できない

例えば「来月の優先目標は新機能の試作」という会話を保存する場合、本人が明示したなら確認済み、過去のメモから読み取っただけなら取込済み、複数のタスクから推論したなら推定です。推定を確認済みへ自動昇格させてはいけません。

レコードには、状態だけでなく更新日、出典、共有範囲も付けます。価格、営業時間、予定、外部サービス仕様のように変化する情報は、確認時点を残し、必要なら要再確認に戻します。

「以前買った」から「今も使っている」、「一度気に入った」から「恒常的な好み」と結論づけるのも避けます。過去の記録、現在の観測、本人の確認を別の情報として扱うことが重要です。

# 自律性を止めるのは3つだけ

AIへ委任する範囲を細かく分けすぎると、実行のたびに確認が発生します。運用上は、停止条件を次の3つにまとめると扱いやすくなります。

## 1. 特定の管理対象資産

退職済みの組織アカウント、権限のない本番資産、共有禁止の環境などです。明示指示がない限り触れません。

## 2. 金銭・契約

設定した上限を超える支出、新しい支払先や支払い手段、契約、解約、継続課金の変更は停止します。金額が上限内でも、年額契約や更新条件が不明なら止めます。

## 3. 不可逆・対外操作

公開、投稿、送信、申請、予約確定、購入確定、大量削除、アカウント削除、権限変更、本人名義の個別メッセージです。

これ以外の読み取り、検索、下書き、ローカル編集、差分作成、可逆的な整理は、別の制約に反しない限り既定自律にします。例えば、AIに記事の下書きを作らせることは許可し、公開ボタンを押すことは停止する、という分離です。

停止するときは、対象、内容、金額、宛先、影響範囲、可逆性を提示します。承認後は、入力しただけか、受付されたか、外部反映したかを再確認します。

# ワークフローで継続運用する

セッション開始時は、`AGENTS.md`、`00_START_HERE.md`、相談に該当する索引と正本だけを読みます。冒頭に「参照したファイル」「確認済みの前提」「不明点」「次の一歩」を出すと、根拠が明確になります。

新しい情報を得たら、正本マップに従って保存先を決め、状態、出典、更新日を付けます。秘密情報、認証情報、金融原本、raw exportはMarkdownへ置きません。月1回、古い情報、重複、inboxの滞留を点検します。

日次ブリーフは情報一覧ではなく、判断のための短い出力にします。今日の結論、予定、3アクション、要返信・要確認、期限、未確認事項、承認が必要な操作を分けると、次に何をすべきかが見えます。

最後に、「完了しました」という主張を検証します。ローカルファイルを変更しただけなら、外部サービスへ反映したことにはなりません。計画、試行済み、実行済み、検証済み、外部反映済みを区別し、差分、終了コード、再読込結果などの証拠を添えます。
